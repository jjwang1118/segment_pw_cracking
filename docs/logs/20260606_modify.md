## 一、`src/prompt_template.py` — 新增 `id=1` prompt

### 背景

原本 `_get_indice()` 只有 `id=0`，語意是「利用帳號資訊猜密碼」，與 knowledge JSON 內容（PCFG 分段結構）語意不符。

### 修改內容

新增 `id=1`，語意明確對應 knowledge JSON：

```python
if id == 1:
    return ("As a targeted password guessing model, your task is to generate likely password candidates based on the structural pattern and segment information provided.")
```

- `id=0`：強調「account information」（run_1 訓練用）
- `id=1`：強調「structural pattern and segment information」（run_2 起訓練用，與 knowledge JSON 內容直接對應）

## 二、`run_search.py` — 排除特殊字元 `<`, `|`, `>` from vocab

### 背景

這三個字元在 Llama tokenizer 的 decode 階段會被組合成假 special token（如 `<|f4p|>`），造成輸出汙染。

### 修改內容

```python
# 修改前
char_ids = [v for k, v in vocab_dict.items() if k not in (tokenizer.eos_token, "\t")]

# 修改後
char_ids = [v for k, v in vocab_dict.items() if k not in (tokenizer.eos_token, "\t", "<", "|", ">")]
```

## 三、`run_search.py` — 新增 `min_len` 支援

### 背景

模型生成的短序列（< 8 字元）佔了大多數輸出，導致 `max_guess_number: 1000` 無法真正輸出 1000 筆有效密碼。

### 修改內容

1. 從 yaml 讀取 `min_len`：
```python
min_len = cfg.get("min_len", 0)
```

2. 寫檔時過濾：
```python
if len(decoded) < min_len:
    continue
```

3. 傳遞給 `contrastive_search`：
```python
results = contrastive_search(..., min_len=min_len)
```

## 四、`util/search.py` — `min_len` 在 beam search 內強制執行

### 背景

`min_len` 只在存檔時過濾治標不治本：EOS 在前幾層就觸發，佔用 `eos_list` 名額，最終有效密碼不足。

### 修改內容

`contrastive_search` 新增 `min_len: int = 0` 參數，在 EOS 判斷前加層數檢查：

```python
batch_eos_over_threshold_index = (
    torch.where(batch_word_probs[:, -1] >= eos_threshold)[0]
    if l >= min_len - 1
    else torch.empty(0, dtype=torch.long, device=device)
)
```

效果：密碼長度 < `min_len` 時 EOS 完全被忽略，beam 繼續延伸。

在主迴圈頂端加入 print，方便確認運行狀態：

## 六、`util/train.py` — 訓練輸出目錄改為 `run_N` 結構

### 背景

每次訓練都寫入同一個 `checkpoints/Llama-3.2-3B-Instruct/`，無法區分不同次訓練實驗。

### 修改內容

新增 `_next_run_dir()` 函數，自動掃描既有 `run_N` 目錄並建立下一個：

```
checkpoints/Llama-3.2-3B-Instruct/
├── run_1/          ← run_1（舊 checkpoint-2517 對應的訓練，placeholder）
│   └── （空）
├── run_2/          ← 本次訓練（prompt template id=1）
│   ├── checkpoint-200/
│   ├── checkpoint-400/
│   └── lora_final/
└── runs/           ← TensorBoard logs（集中）
    └── run_2/
```

TensorBoard 指令不變：
```bash
tensorboard --logdir "checkpoints/Llama-3.2-3B-Instruct/runs"
```

## 七、`util/train.py` — 修復 LoRA + gradient checkpointing 梯度錯誤

### 錯誤

```
RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn
```

### 原因

`gradient_checkpointing=True` 時，autograd 需要 embedding 輸出帶有 `grad_fn`，PEFT 預設不開啟。

### 修改內容

```python
model = apply_lora(model, config["train"]["lora_config"])
model.enable_input_require_grads()  # required for gradient_checkpointing + LoRA
```
