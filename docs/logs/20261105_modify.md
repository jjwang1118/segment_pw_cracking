## 新增 prompt id=10（純 tag + 段落編號）

結構改為 `<seg_i,tag_i>`，沿用 id=6 的 instruction，只讀 `Tags`（忽略
`Siblings` / `Account`），不需重新產生資料。id=9 維持不變，舊實驗可重現。

### 改動

- `src/prompt_template.py`：新增 id=10、`build_seg_tag_knowledge()`、
  `prompt_convert_seg_tag()`。
- `util/pw_tokenize.py`：`process_train_targeted()` 新增 id=10 分支。
- `run_eval.py`：`_build_prompt()` 新增 id=10 分支。
- `util/train.py`：快照註解改為 id=9/10 使用 `knowledge_format`。
- `config/knowledge_format.yaml`：更新註解，設定值未改。id=10 與 id=9 共用
  `knowledge_format`，`passllm_opts` 僅 id=9 使用。
- `docs/promt.md`：新增 id=10 說明。

`train_config.yaml`、`search.yaml` 未改，仍是 run_30 的設定。`run_search.py`
未支援 id=10，正式評估使用 `run_eval.py`。

### 驗證

- COMB backoff 測試集前 2,000 筆，json / passllm 兩種組裝皆正確，序列最長
  143 / 140 tokens，未超過 `max_length=512`。
- 確認 id=10 不會帶入 `Siblings` / `Account`。
- 尚未實際訓練或評估 id=10。

### 發現的既有問題（未修）

訓練與評估的 prompt token 在 instruction / knowledge 邊界不一致：

- 訓練：instruction 與 knowledge 分開 tokenize，knowledge 開頭多出 SentencePiece
  前綴空白（`▁{"`、`▁` + `<0x0A>`）。
- 評估：整串 tokenize（`{"`、`<0x0A>`）。
- 抽樣 2,000 筆：id=5、6、7、9（json / passllm）、10（json / passllm）全數不一致；
  id=7、9 已確認差異只在邊界，其後 token 相同。

修正方式會影響與舊實驗的可比性，待使用者決定。

## id=10 新增 `seg_tag_clues` 線索選項

`config/knowledge_format.yaml` 新增 `seg_tag_clues`，可選 `account`、`sibling`；
預設 `[]`，維持純 tag。上一節「只讀 `Tags`」的行為改為由此選項控制。

### 改動

- `src/prompt_template.py`：新增 `seg_tag_system_prompt()`，`build_seg_tag_knowledge()`
  與 `prompt_convert_seg_tag()` 支援線索。
- `util/pw_tokenize.py`、`run_eval.py`：傳入 `seg_tag_clues`。
- `util/train.py`：讀取 `seg_tag_clues`，並寫入訓練快照。
- `docs/promt.md`：更新 id=10 說明。

### 行為

- instruction 只列出實際提供的線索；`[]` 時與 id=6 相同。
- passllm 模式用 `<account,...>`、`<sibling,...>` 標記線索邊界。
- 選了線索但資料集缺欄位時直接報錯，避免像 run_30 一樣靜默略過 account。
