## 新增 prompt template id=3b 與 id=4b

**設計**：

| | 3b | 4b |
|---|---|---|
| User prompt 描述 | `get_explanation()`（自然語言，無 raw tag 名稱） | `get_explanation()`（同左） |
| User prompt 結構 | `<SEG1>...<SEGN>` 佔位符（同 id=3） | `<SEG1>...<SEGN>` 佔位符（同 id=3） |
| System text | id=3 文字 + 每 segment 獨立一行指示 | id=4 風格（自然語言版），每 segment 獨立一行指示 |
| Assistant 輸出（訓練） | 每 segment 獨立一行（同 id=4） | 每 segment 獨立一行（同 id=4） |
| 與 id=3 的差異 | 只改 assistant 輸出格式 | 加上更明確的 system text |
| 與 id=4 的差異 | 描述改用自然語言（不暴露 tag 名如 `number2`） | 描述改用自然語言（不暴露 tag 名如 `number2`） |

**修改的檔案**：

- `src/prompt_template.py`：新增 `_get_indice("3b")` / `_get_indice("4b")`；新增 `prompt_convert_structure_placeholder_newline`（id=3b）/ `prompt_convert_no_tag_newline`（id=4b）作為 `prompt_convert_structure_placeholder` 的薄封裝
- `util/pw_tokenize.py`：`process_train_targeted` 新增 `elif template_id in ("3b", "4b")` 分支（knowledge_text 同 id=3）；password_ids 的 per-segment 換行邏輯從 `template_id == 4` 擴展為 `template_id in (4, "3b", "4b")`
- `run_eval.py`：`_build_prompt()` 加入 "3b"/"4b" routing；vocab / newline_id 選擇從 `== 4` 擴展為 `in (4, "3b", "4b")`
- `run_search.py`：`run_contrastive_search` 與 `run_dynamic_beam_search` 同步更新 vocab / newline_id 條件

## prompt template id=5 — 重設計

**問題**：舊版 id=5 訓練時 User prompt 含實際 token 字串（`<nn>dragon<number2>99<special1>!`），推論時卻只有 tag（`<nn><number2><special1>`），造成 train/inference 不對稱，模型訓練時等於在「看答案抄」。

**新設計**：訓練與推論 User prompt 完全一致，均只含 tag 名稱佔位符，無任何 segment 文字或自然語言描述：

```
{"password structure": "<nn><number2><special1>"}
```

Assistant 輸出格式不變（空格分隔字元序列，如 `d r a g o n 9 9 !`）。

**修改的檔案**：

- `src/prompt_template.py`：`_get_indice(5)` 更新 system prompt（移除「natural-language constraints」錯誤描述）；`prompt_convert_inline` 移除 tokens 參數，只用 tag 名稱建立 structure
- `util/pw_tokenize.py`：`process_train_targeted` id=5 分支從 `<tag>segment` 改為 `<tag>`
- `docs/promt.md`：更新 id=5 章節，說明訓練推論 prompt 完全一致
