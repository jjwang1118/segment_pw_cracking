## 調整 `config/search.yaml` — 重評 run_21 於 COMB_MIX 測試集

### 背景
發現 `run_21`（id=5，tag-only 基準）先前的評估 `gen/eval_results_id5_run_21_..._COMB_..._5000.jsonl`
用的是 **plain COMB** 測試集（實際評估的 5,000 筆密碼 100% 落在 `COMB/backoff/split/test_data.jsonl`、0% 落在 COMB_MIX），
與 run_22/23/04 的 **COMB_MIX** 測試集（同一組 5,000 筆）交集僅 1 筆。
但 `run_21` 的 `train_config_snapshot.json` 顯示它是**訓練於 COMB_MIX**（`COMB_MIX/backoff`，id=5，LoRA r16/α32/qkv、lr 2e-4），
故評估集與訓練分佈/其他三 run 不一致。為做 COMB_MIX 同集對照（比較報告 Section 1），需重評。

### 修改（`config/search.yaml`）
1. `constrained_beam_search.prompt_template_id`: `7` → **`5`**（run_21 為 tag-only；跑 run_22 需改回 7）
2. `eval.model_path`: `run_22/lora_final_7200` → **`run_21/lora_final_5500`**
3. `eval.test_data_path`: 維持 `combine_acc_sibling/sibling/backoff/split/test_data.jsonl`（與 run_22 同一份；id=5 只讀 `Tags`、忽略 `Siblings` 欄）
4. `eval.max_eval_samples`: 維持 `5000`（取前 5,000 筆，row-aligned → 與 run_22/23/04 同一組 5,000 密碼）
5. `eval.eval_output_file_name`: → **`eval_results_id5_run_21_Mist7B_id5_COMB_MIX_constrain_5000.jsonl`**

`search_type` 維持 `constrained_beam_search`（`fallback_to_dynamic: true`，與 run_21 原評估同法）。
執行：`python run_eval.py`（依現行 HPC 流程提交）。輸出即為 run_21@COMB_MIX，供比較報告 Section 1 同集對照。

（後續：使用者將 `eval.test_data_path` 改為 `semanticPCFG/COMB_MIX/backoff/split/test_data.jsonl`——tag-only 檔，更貼近 run_21 訓練用的 `dataset_path`；已驗證其前 5,000 筆密碼**順序與集合**與 run_22/23/04 完全一致。）
