# 2026-07-27 修改紀錄

## config/search.yaml：修正 eval.test_data_path 指向舊資料集，導致 id=7 eval 靜默退化成 id=5

run_19（`checkpoints/Mistral-7B-v0.1/run_19`）訓練時用的是 `datasets/processed/semanticPCFG/combine/backoff`（含 `Siblings` 欄位）、`prompt_template_id: 7`，但 `config/search.yaml` 的 `eval.test_data_path` 仍指向舊的 `datasets/processed/semanticPCFG/COMB/backoff/split/test_data.jsonl`——兩份資料筆數相同（train 262,263 / test 13,513）、欄位幾乎一樣，只差 `COMB` 版沒有 `Siblings` 欄位，很容易忽略。

`run_eval.py:103-105` 對 template_id 7 會呼叫 `prompt_convert_sibling_tag(..., entry.get("Siblings"))`，`COMB` 資料的 `entry.get("Siblings")` 會回傳 `None` → `siblings = []`，eval 不會報錯，但每一筆 prompt 的 sibling passwords 都會是空清單，等同用 id=5 的效果在跑 id=7 的模型，完全沒有測試到訓練時學到的 sibling-conditioning 能力。這正是 [20260725_modify.md](20260725_modify.md) 「待決定，尚未修正」段落點出過的同一個風險（`util/pw_tokenize.py:144` 那段），只是這次出現在 eval 端而非訓練端。

**修正：** `eval.test_data_path` 改回 `datasets/processed/semanticPCFG/combine/backoff/split/test_data.jsonl`，與 run_19 訓練時的資料集一致。
