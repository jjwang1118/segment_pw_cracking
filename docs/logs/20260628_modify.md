# 2026-06-28 修改記錄

## 修正 SentencePiece tokenizer 的 token ID 錯位問題

### 問題根因
`get_alpa()` 對 SentencePiece tokenizer（Mistral/LLaMA）存在兩個 bug，導致 Mistral-7B 評估破解率為 0：

1. **`▁X` space-prefix 問題**：`tokenizer(w)["input_ids"][-1]` 取到的是帶 space-prefix 的 `▁d` token。
   組合 decode 時，第 2 個以後的每個 token 都會前置空白：
   `decode([▁d, ▁r, ▁a]) → "d r a"` ≠ `"dra"`，密碼永遠比對不上。

2. **推論 decode 直接與 `real_pw` 比對**（`run_eval.py:309`），而非做任何後處理，
   因此上述空白導致 1000 個候選全部 miss。

### 修改內容

#### `util/pw_tokenize.py` — `get_alpa()`
- 加入 SentencePiece 偵測：對 `"d"` 和 `"r"` 組合 decode，若結果 ≠ `"dr"` 即為 SPM。
- SPM 路徑：優先查 byte-level token `<0xHH>`（如 `<0x64>` for `d`），組合 decode 不帶空白。
  fallback 順序：`<0xHH>` → `convert_tokens_to_ids(w)` → pipeline。
- tiktoken（Qwen）路徑：原邏輯不動。

#### `run_eval.py` — `run_eval()`
- 在 vocab 初始化後加入 `_needs_space_strip` flag，用 `vocab_dict['d']` 做 probe（而非重新 tokenize），
  確保 `get_alpa()` 修正後此 flag 自動關閉。
- decode 候選時若 flag 為 True，呼叫 `.replace(" ", "")` 去除殘留空白。

### 驗證
| Tokenizer | 修前 `encode→decode("dragon99!")` | 修後 |
|---|---|---|
| Mistral-7B SentencePiece | `"d r a g o n99 !"` ✗ | `"dragon99!"` ✓ |
| Qwen3-4B tiktoken | `"dragon99!"` ✓ | `"dragon99!"` ✓（不受影響）|

### 後續行動
- 使用修正後的 `get_alpa()` 重新訓練 Mistral-7B（run_3/template_5 需要 retrain）。
- 重訓完成後，`_needs_space_strip` 對 Mistral 也會自動為 False（byte token 個別 decode 正確）。
