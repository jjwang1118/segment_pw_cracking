# 2026-10-27 修改記錄

## 新增 PagPassGPT 結構標籤 pipeline

參考 `run_pcfg_combine_acc_sibling.py` 的風格（讀已切好的 semanticPCFG split
JSONL → 逐列改寫欄位 → 寫平行資料夾），新增一條 PagPassGPT 結構標籤管線。

### 新增檔案

- **`config/pagpass_segment.yaml`** — pipeline 設定。
  - `pagpassgpt_root`: PagPassGPT repo 路徑（`/home/u4996812/PagPassGPT`，提供 `tools.get_pattern`）
  - `input_root` + `ref_tagtype`: 密碼與 train/test 切分來源（semanticPCFG 已切好的 split）
  - `output_root`: `datasets/processed/PagPassGPT`
  - `datasets`: 要處理的資料集清單（預設 `rockyou-75`）

- **`run_pagpass_segment.py`** — 進入點。
  - 重用 PagPassGPT `tools.password_pattern.get_pattern`（字元類別連續段：L 字母 / N 數字 / S 符號）
  - 不重新 sample / split：讀 `{input_root}/{dataset}/{ref_tagtype}/split/{train,test}_data.jsonl`，
    逐列用 `Password` 重算 `Tokens`/`Tags`，其餘欄位（source 等）原樣保留
  - 結構標籤範例：`love999!` → Tags `L4|N3|S1`、Tokens `love|999|!`
  - 輸出 `{output_root}/{dataset}/split/{train,test}_data.jsonl` + `length_distribution.json`
  - CLI：`--dataset`、`--force`

### 與 semanticPCFG 的差異

| | semanticPCFG | PagPassGPT |
|---|---|---|
| Tag 語意 | backoff/pos/pos_semantic（語意） | 純結構（字元類別+長度） |
| 目錄層級 | `{dataset}/{tagtype}/split/` | `{dataset}/split/`（無 tagtype 層） |
| 切分 | 重新 sample+split | 沿用 semanticPCFG 切分，僅重算 Tag |

因密碼集合與切分完全沿用 semanticPCFG，兩套 Tag 可直接公平比較。

### 驗證

對 `rockyou-75` 執行成功（train 7,963 / test 402 列）。整合檢查：
- 列數與 semanticPCFG 來源一致
- `Password` 逐列對齊（順序不變）
- `Tokens` 去除 `|` 後等於原密碼（切回可還原）

## 新增 PagPassGPT + PassLLM PII 合併 pipeline

對應 `run_pcfg_combine_acc_sibling.py`，流程完全相同（讀 PassLLM PII、
row-index join、出 `sibling` / `sibling_account` 兩 variant），**唯一差別是
Tokens/Tags 用 PagPassGPT `get_pattern` 現場生成，而非讀 semanticPCFG 語意 tag**，
因此沒有 tagtype 迴圈。

### 新增檔案

- **`run_pagpass_combine_acc_sibling.py`**
  - 複用 `run_pagpass_segment.py` 的 `load_config` / `get_segmenter` / `segment_and_tag`
  - Password + 切分來源：`{input_root}/{dataset}/{ref_tagtype}/split/`（tag 被忽略、重算）
  - PII 來源（專案樹外）：`/home/u4996812/passllm/data/{dataset}/{train,test}_addacc.json`
  - 輸出：`{output_root}/combine_acc_sibling[_{dataset}]/{sibling,sibling_account}/split/`
    （COMB_MIX 不加後綴，與原腳本對齊）
  - CLI：`--dataset`（預設 COMB_MIX）、`--sibling-limit`（預設 5）、`--force`
  - 保留原腳本的 row-count + 逐列 Password 比對，不符即 raise

### 驗證

對 `Collection1_acc_pii` 執行成功（train 302,095 / test 16,278 列，兩 variant）。
row-index join 全數通過；輸出與 semanticPCFG 版同列的 Password/Siblings/Account
一致，僅 Tags 改為結構形式（如 `kerem11` → `L5|N2`）。

注意：`--sibling-limit` 預設 5；若要與既有 semanticPCFG 的
`combine_acc_sibling_Collection1`（每列 10 個 sibling）對齊，需加 `--sibling-limit 10`。
