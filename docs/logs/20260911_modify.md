## 新增 `run_pcfg_combine_acc_sibling.py` — COMB_MIX 加入 PassLLM PII（sibling + account）

### 目的
把已處理好的 COMB_MIX PCFG-native tagged jsonl
（`datasets/processed/semanticPCFG/COMB_MIX/{backoff,pos,pos_semantic}/split/{train,test}_data.jsonl`）
與 PassLLM PII 合併，產出兩個變體資料集：

- **變體 A `sibling`**：加入 `Siblings` 欄（`Knowledge."Old password"`，json.dumps 的 list）
- **變體 B `sibling_account`**：加入 `Siblings` + `Account` 欄（`Knowledge.Account` 原始字串）

每個 split（train/test）各產出兩個檔案（兩個變體），共 2 變體 × 3 tagtype × 2 split = 12 個 jsonl。

### 資料來源與對齊
- Tagged：`datasets/processed/semanticPCFG/COMB_MIX/{tagtype}/split/`
- PII：`/home/u4996812/passllm/data/COMB_MIX/{train,test}_addacc.json`
  （每列含 `Knowledge.Account` + `Knowledge."Old password"` + `password`，專案外路徑，`datasets/passllm/` 為 gitignored）
- Join 方式：row-index join，沿用 `run_pcfg_combine_sibling.py` 的全掃描 Password/password 驗證（不符即 raise）
- 對齊驗證（2026-09-11）：train 378,719 / test 7,466 rows，**0 mismatch**，Account 與 Old-password 覆蓋率皆 100%

### 輸出
```
datasets/processed/semanticPCFG/combine_acc_sibling/
  sibling/{backoff,pos,pos_semantic}/split/{train,test}_data.jsonl          # +Siblings
  sibling_account/{backoff,pos,pos_semantic}/split/{train,test}_data.jsonl  # +Siblings +Account
```
每個 variant/tagtype 目錄含 `split/` 子目錄，符合 `util/train.py:load_datasets()` 的 `{dataset_path}/split/` 規則。
`sibling-limit` 預設 5（與 `run_pcfg_combine_sibling.py` 一致）。

### JSONL 格式範例
變體 A：
```json
{"Password":"25031984v","Tokens":"25031984|v","Tags":"number8|char1","source":"COMB_MIX","Siblings":"[\"25031984vb\", \"5031984vb\", \"25033988vb\", \"v_bolshova\", \"bv48913052\"]"}
```
變體 B（多 `Account`）：
```json
{"Password":"25031984v","Tokens":"25031984|v","Tags":"number8|char1","source":"COMB_MIX","Siblings":"[...]","Account":"v_bolshova"}
```

### 備註
- `Siblings` 沿用 id=7 的 json 格式（非 pipe-joined），以免含 `|` 的舊密碼被切壞。
- `Account` 目前以原始字串存放；尚無對應的 prompt template 消費 `Account` 欄（`util/pw_tokenize.py` / `src/prompt_template.py` 目前只處理 `Siblings`，id=7）。若要訓練變體 B，需新增對應 template。
- 使用：`python run_pcfg_combine_acc_sibling.py`（預設 dataset=COMB_MIX、全 tagtype、兩變體；`--force` 覆寫）

## 新增 prompt template id=9（account + sibling）與 `knowledge_format` YAML 開關

### 目的
替 `sibling_account` 變體資料新增 prompt template（id=9），並提供一個 YAML 開關
`knowledge_format`，可在**兩種 knowledge 拼接方式**之間切換（訓練 + 評估端都吃得到）：

- **`json`（目前這種方式）**：單一 JSON object
  `{"password structure": "<tag>...", "account": "...", "sibling passwords": [...]}`，
  instruction 後直接相接（無換行），風格同 id=5/7/8。instruction 用 `_get_indice(9)`。
- **`passllm`（論文串接格式）**：`instruction + "\n" + [account + 舊密碼直接黏接]`，
  **無任何分隔符**（`separator=""`），輔助資訊之間不插 `</s>`；整條序列**只有最末端 1 個 EOS**
  （管線在 target 後補的那個）。instruction 重用 `_get_indice(0)`（PassLLM 原始 instruction）。

兩種模式**資料完全相同、只差呈現**，為 apples-to-apples 對照。**target 一律用我們的 95-char
逐字元編碼（`encode_limit`），不採 PassLLM 的 subword**——維持 `util/search.py` constrained
decoding / eval 的相容性。loss 皆只壓 target+EOS。

### passllm_opts（只在 knowledge_format=passllm 生效）
| key | 預設 | 說明 |
|-----|------|------|
| `include_structure` | `false` | 是否保留 `<tag>` 結構（論文原始=false，無結構）|
| `separator` | `""` | account/舊密碼之間的分隔符（論文=直接黏接）|
| `account_first` | `true` | account 放在 sibling passwords 之前 |

> 注意：`separator` 設為 `"</s>"` 時，tokenizer 會把它編成**真正的 EOS token（id=2）**塞進 prompt
> 中間（經實測）；論文採直接黏接（`""`），故預設為空字串、序列中只有最末端 1 個 EOS。
> passllm 模式無 `<tag>` 結構 → 評估請用 `dynamic_beam_search` / `contrastive_search`，
> 勿用 `constrained_beam_search`（train/infer 會不一致）。

### 完整 prompt 對照（COMB_MIX row0：密碼 `25031984v`、account `v_bolshova`、結構 `<number8><char1>`）
**json：**
```
...for each segment in order.{"password structure": "<number8><char1>", "account": "v_bolshova", "sibling passwords": ["25031984vb", "5031984vb", "25033988vb", "v_bolshova", "bv48913052"]}
```
**passllm：**
```
...to guess the password.\nv_bolshova25031984vb5031984vb25033988vbv_bolshovabv48913052
```
（兩者之後接 target `25031984v` + 單一最末端 EOS；已用 Mistral tokenizer 端到端驗證：各 1 個 EOS、loss 壓 10 tokens。）

### 使用
- 訓練：`train_config.yaml` 設 `prompt_template_id: 9` + `knowledge_format: json|passllm`，
  `dataset_path` 指向 `datasets/processed/semanticPCFG/combine_acc_sibling/sibling_account/{tagtype}`。
- 評估：`search.yaml` 對應 search 區塊設 `prompt_template_id: 9` + `knowledge_format`，
  `test_data_path` 指向同資料夾的 `test_data.jsonl`。
