# 2026-11-03 修改記錄

## 修正 train_config.yaml 的 dataset_path（PagPassGPT 訓練）

為了用 PagPassGPT 資料訓練，檢查 `config/train_config.yaml` 相容性。

### 問題

`dataset_path` 原本寫到底層檔案：
```
datasets/processed/PagPassGPT/combine_acc_sibling/sibling/split/train_data.jsonl
```
但 `util/train.py:load_datasets()` 會自行接 `/split/{train,test}_data.jsonl`
（`util/train.py:39`），因此實際會去找
`.../sibling/split/train_data.jsonl/split/train_data.jsonl`，必定失敗。

### 修正

改成只寫到 variant 目錄：
```
dataset_path: datasets/processed/PagPassGPT/combine_acc_sibling/sibling
```

### 相容性確認（PagPassGPT 結構 Tag × prompt id=7）

- prompt id=7 的 converter `prompt_convert_sibling_tag` 用 **inline `<tag>`**
  （`<L4><N3><S1>`），**不呼叫 `get_explanation`**，因此 PagPassGPT 的結構 Tag
  直接可用；`get_explanation('L4')` 查無而回傳自身，對 id=7 無影響。
- 資料 variant 相符：config 指向 `sibling`（只有 Siblings），id=7 正好用
  Siblings、不用 Account。
- `load_datasets` 直接讀現成 train/test，不重切（`expected_ratio`/`split_ratio`
  在此路徑未使用）。

### Smoke test

- 修正後 train/test 兩檔皆載得到。
- id=7 以 PagPassGPT 列組 prompt，結構正確（如 `<N8><L1>` + sibling passwords）。

### 待使用者決定（未改）

- 模型為 `Mistral-7B-v0.1` + `lora_kind: lora`（bf16 非量化）。7B bf16 權重約
  14GB，RTX 5070 12GB 可能 OOM；若要在 12GB 上跑 7B，建議改 `lora_kind: qlora`
  （4-bit NF4）。此為既有設定、非 PagPassGPT 造成，故未動。
