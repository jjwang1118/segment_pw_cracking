## 新增 prompt id=7：結合姊妹密碼與 tag 結構

設計動機與細節見 [docs/promt.md](../promt.md) `#### id=7` 段落；`sibling passwords` + `password structure`（沿用 id=5 inline `<tag>`）JSON 包裝，訓練/推論 User prompt 完全相同。System text：

> "As a targeted password guessing model, your task is to generate likely password candidates that match the given password information. The password structure is represented as a sequence of `<tag>` placeholders, and sibling passwords, if any, are prior passwords from the same account. Do not output the tag placeholders. Generate only the password characters for each segment in order."

### 新增 run_pcfg_combine_sibling.py

- 合併 `datasets/passllm/{TRAIN,TEST}.json`（`Knowledge."Old password"`）與 `datasets/processed/semanticPCFG/COMB/{tagtype}/split/{train,test}_data.jsonl`，用 row index join
- 執行前已用全量掃描驗證兩份資料 Password 欄位逐筆一致（train 262,263 筆 / test 13,513 筆，0 筆錯位）；`build_siblings_column()` 仍保留逐筆比對，一旦未來資料更新導致行序不符會直接 raise 中止，不會產出錯位資料
- 新增 `Siblings` 欄位：取 `Old password` 前 5 筆，`json.dumps()` 成字串存入（而非 pipe-separated），理由是姊妹密碼可能含 `|` 字元，JSON 包裝可自動處理跳脫，不需額外過濾；亦與 [comparison_PassLLM_vs_PCFG-LLM_COMB.md](../reports/comparison_PassLLM_vs_PCFG-LLM_COMB.md) 第 7 節「PassLLM 舊 Prompt（JSON 包裝）優於新 Prompt（`</s>` 串接）」的結論一致
- 輸出至 `datasets/processed/semanticPCFG/combine/{tagtype}/split/{train,test}_data.jsonl`（三種 tagtype 皆已產生；`split/` 這層是 code review 後修正加上的，見下方「code review 與修正」）
- 額外驗證：姊妹密碼清單與待猜目標密碼之間無自我洩漏（train/test 皆 0 筆 self-leak）、無 test→train 洩漏（0 筆）；僅有 501 筆（0.19%）train 目標密碼因真實密碼重用巧合出現在某筆 test 資料的姊妹密碼清單中，屬資料本身特性，非 join 邏輯問題，暫不處理
