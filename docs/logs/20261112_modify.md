## 問題：job 459793 (Mistral-7B plaintext full FT) 在首個 checkpoint 崩潰

- 現象：訓練跑到 step 500（`save_steps: 500`）`Writing model shards: 0%` 後停住。
- 實際狀態：`sacct` 顯示 **FAILED @ 2026-11-11 22:42:11**（非卡住，已結束）。`.out` 無 traceback。
- 根因：**`/home` 100% 爆滿（剩 ~840M）**。checkpoint 寫在 home 下的 `checkpoints/`，寫 7B 完整 model shards（數十 GB）時磁碟寫不下而崩潰。`checkpoint-500/` 僅有小 JSON、無 safetensors 為證。
- `/work` 僅使用 24%（2.8P 空閒）。

## 解法（方案 A，選項 ②）：模型與 checkpoint 全部遷至 /work

1. **搬移 base 模型**
   `models/Mistral-7B-v0.1` → `/work/u4996812/models/Mistral-7B-v0.1`
   - `rsync -a` 搬移，校驗兩邊皆 14 檔 / 27G 一致後，刪除 home 原件。

2. **`config/train_plaintext.yaml`**
   - `model_path: models` → `model_path: /work/u4996812/models`
   - `output_dir: checkpoints` → `output_dir: /work/u4996812/checkpoints`

3. **`run_train_plaintext.py`（階段一最終模型路徑）**
   - 第 218 行 `final_dir = PROJECT_ROOT / "models" / ...`（寫死 home）
     → `final_dir = PROJECT_ROOT / tc["model_path"] / ...`
   - 結尾 print 的 `model_path=models` → `model_path={tc['model_path']}`
   - 效果：最終 ~27G 完整權重也落在 `/work/u4996812/models/Mistral-7B-v0.1_1`，home 不再被吃。
   - 影響：階段二（`run_train.py`）引用時 `model_path` 需設為 `/work/u4996812/models`。

4. **損壞的 `checkpoint-500/`**：由使用者自行刪除。

## 變更：plaintext 微調由 full fine-tune 改為 LoRA

**動機**：7B 全參數微調的 optimizer state checkpoint 數十 GB，是先前爆盤崩潰的根因之一；改 LoRA 後訓練中 checkpoint 只存 adapter（數 MB），顯存與磁碟壓力都大幅下降。

### `config/train_plaintext.yaml`
- 頂層新增 `lora_kind: lora`（可選 `qlora` 4-bit）與 `qlora_train_overrides`（`bf16:false` / `optim:paged_adamw_8bit`）。
- `learning_rate`: `1e-5` → `2e-4`（LoRA 用較大 LR）。
- `train:` 下新增 `lora_config`（r=16, target_modules=q/k/v_proj, alpha=32, dropout=0.2, bias=none）。
- 標頭註解由「full fine-tune」改為「LoRA 微調」。

### `run_train_plaintext.py`
- import `prepare_model_for_kbit_training`（peft）、`apply_lora`（util.train，複用既有實作）。
- `build_model_and_tokenizer`：依 `lora_kind` 決定 bf16 載入（lora）或 4-bit NF4 量化載入（qlora）。
- `main`：套 LoRA（qlora 先 `prepare_model_for_kbit_training` 並套用 overrides）→ `apply_lora` → lora 時 `enable_input_require_grads` → `print_trainable_parameters`；移除舊的手動 gradient_checkpointing 區塊（改交由 TrainingArguments 依 tc 啟用）。
- 最終模型：先存純 adapter 至 `run_N/lora_final`；再 `merge_and_unload` 把 LoRA 合併回 base 存成完整模型至 `<model_path>/<name>_<train_num>`，**階段二 (`run_train.py`) 仍可直接當 base 載入，無需改動**。QLoRA 無法 merge，僅輸出 adapter（階段二需 base+adapter 載入）。

### 驗證
- `py_compile`、YAML 解析、`apply_lora` / `prepare_model_for_kbit_training` import 均通過。

### 追加：最終模型命名改為 `-plaintext`
- 原 `<model_name>_<train_num>`（`Mistral-7B-v0.1_1`）是 full fine-tune 時代的版本化命名，改 LoRA 後語意不符。
- `run_train_plaintext.py`：`final_dir` 改為 `<model_path>/<model_name>-plaintext`
  → `/work/u4996812/models/Mistral-7B-v0.1-plaintext`（與 checkpoint 目錄名對齊）。
- `config/train_plaintext.yaml`：移除已失效的 `train_num` 鍵，改註解說明新命名。
- 階段二引用：`model_path=/work/u4996812/models`, `model_name=Mistral-7B-v0.1-plaintext`。

### 再追加：最終模型依 run_N 分目錄（不覆蓋）
- 問題：固定路徑 `<model_name>-plaintext` 會讓多次 run 的最終模型互相覆蓋。
- `run_train_plaintext.py`：`final_dir` 改為 `<model_path>/<model_name>-plaintext/<run_dir.name>`
  → `/work/u4996812/models/Mistral-7B-v0.1-plaintext/run_N`，與 checkpoints 的 run 編號對齊，每次訓練各存一份。
- 階段二引用改為：`model_path=/work/u4996812/models`, `model_name=Mistral-7B-v0.1-plaintext/run_N`。
