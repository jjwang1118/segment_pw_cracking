## Convert Collection1 PII dataset via existing combine pipeline

Goal: turn the Collection1 PII dataset into PCFG-native `sibling_account`
training JSONL, reusing the existing `run_pcfg_combine_acc_sibling.py` join
pipeline (same convention as COMB_MIX) rather than a bespoke script.

### Sources (verified row-aligned, 302,095 train / 16,278 test)
- Raw self-contained: `datasets/processed/semanticPCFG/Collection1_pii_sibling/{TRAIN,TEST}.jsonl`
  (rows `{account, password, sister_passwords}`)
- PassLLM PII: `/home/u4996812/passllm/data/Collection1_acc_pii/{train,test}_addacc.json`
  (rows `{Knowledge:{Account, Old password}, password}`) — confirmed identical
  password order to the raw JSONL (0 mismatches on full scan).

### Step 1 — tagged source (prerequisite for the join script)
`run_pcfg_combine_acc_sibling.py` only *joins*; it needs a row-aligned tagged
source that `run_pcfg_segment.py` cannot produce (the latter filters/samples/
re-splits, breaking alignment). Generated one with a one-off scratchpad tagging
step (not committed) that segments+tags each password IN ORDER:
  `datasets/processed/semanticPCFG/Collection1_acc_pii/{tagtype}/split/{train,test}_data.jsonl`
  columns Password/Tokens/Tags/source, all tagtypes, 0 fallbacks.

### Step 2 — edit `run_pcfg_combine_acc_sibling.py`: namespace OUT_DIR by dataset
The script hardcoded `OUT_DIR = SPLIT_DIR / "combine_acc_sibling"` regardless of
`--dataset`, so it collided with the existing COMB_MIX output. Replaced the
constant with `out_root(dataset)`:
  - `COMB_MIX` -> `combine_acc_sibling` (unchanged, backward compat)
  - other      -> `combine_acc_sibling_{dataset}`
Docstring updated accordingly.

### Step 3 — run join (keep ALL siblings per user)
```
python run_pcfg_combine_acc_sibling.py --dataset Collection1_acc_pii \
    --sibling-limit 100000000 --force
```
Output (both variants the script emits — `sibling` and `sibling_account`):
  `datasets/processed/semanticPCFG/combine_acc_sibling_Collection1_acc_pii/{variant}/{tagtype}/split/{train,test}_data.jsonl`
302,095 train / 16,278 test per tagtype; 100% siblings + Account; no truncation
(e.g. kerem11 keeps all 10 siblings). Default `--sibling-limit` is 5, which
would truncate — overridden here because the user wants all siblings kept.
