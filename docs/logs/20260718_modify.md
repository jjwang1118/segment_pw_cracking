# 2026-07-18 修改紀錄

## train_h200.sh
- 在 `python run_train.py` 前加入備註，說明訓練中斷後如何用 `--resume checkpoints/<model_name>/run_N/checkpoint-XXXX` 續訓，以及續訓會沿用同一 run 目錄、接續 optimizer/scheduler 狀態，不會重算 epoch。

## util/train.py
- 新增 config 快照機制：每次開新 run 時，把當下完整 config 存成 `checkpoints/<model>/run_N/train_config_snapshot.json`。
- `--resume` 續訓時改為優先讀該 run 的快照 json 覆蓋掉當下 `config/train_config.yaml`，避免中途修改 config（尤其 `lora_config` 的 r/target_modules/lora_alpha）導致續訓時模型架構跟 checkpoint 對不上而崩潰。
- 若該 run 沒有快照（快照機制之前建立的舊 run，如 run_3～run_17），續訓時會印出警告並退回使用目前的 `config/train_config.yaml`，不會擋住續訓。
- 已用 stub 過重運算部分（model/tokenizer/trainer）的假資料跑過三種情境驗證：新 run 存快照、有快照時續訓讀快照覆蓋 live config、無快照時退回 live config 並印警告，皆行為正確。
